# VISTA-AI

VISTA-AI predicts customer satisfaction (CSAT) from a recorded customer-service call. It listens to the whole conversation, combines **what was said** (text) with **how it was said** (tone of voice), and assigns one of four classes:

| Label | Class | Meaning |
|---|---|---|
| 0 | Very Unsatisfied | Angry or shouting, problem not solved |
| 1 | Unsatisfied | Flat tone, problem not solved |
| 2 | Satisfied | Flat tone, problem solved |
| 3 | Very Satisfied | Happy or enthusiastic, problem solved |

The Streamlit app also explains each prediction: which turns of the call mattered most, whether the decision leaned on the words or the voice, and a short plain-language summary.

## How it works

1. **Transcribe.** The audio is converted to 16 kHz mono and split into turns by Whisper.
2. **Embed each turn.** Every turn gets two 768-d vectors: a voice embedding from [WavLM](https://huggingface.co/microsoft/wavlm-base-plus) and a text embedding from [MPNet](https://huggingface.co/sentence-transformers/all-mpnet-base-v2).
3. **Fuse and classify.** A transformer model lets the text and voice vectors attend to each other, reads the turns in order, and outputs the 4-class prediction.

Two model versions are trained and compared side by side:

- **V1** (`DualTransformerClassifier`): cross-modal attention, a 2-layer transformer over turns, mean pooling. About 2.1M parameters.
- **V2** (`EnhancedDualTransformerClassifier`): adds a residual MLP adaptation block and a learnable `[CLS]` token for pooling. About 2.7M parameters.

Training has two stages. Stage 1 trains on synthetic calls (scripts generated by an LLM and voiced with ElevenLabs, then augmented with noise, reverb and telephone filtering). Stage 2 freezes that model and trains a small adapter on real calls, and the adapter is rejected automatically if it hurts accuracy on the synthetic validation set.

## Results

On 13 real calls the models never trained on (YouTube and uploaded recordings):

| Model | Synthetic validation | Real-call test |
|---|---|---|
| V2 | 99.4% | 100.0% (13/13) |

The real test set is small, so one call changes the score by about 7.7 points. Treat these numbers as early evidence, not a final benchmark.

## Getting started

**Requirements:** Python 3.12+, [ffmpeg](https://ffmpeg.org/) on your PATH, and a GPU if available (Apple Silicon MPS, then CUDA, then CPU). The app's YouTube URL input also needs [Deno](https://deno.com/), a JavaScript runtime that `yt-dlp` uses to fetch YouTube audio. File upload and microphone input work without it.

Install ffmpeg and Deno:

```bash
winget install Gyan.FFmpeg              # Windows
winget install DenoLand.Deno            # Windows
brew install ffmpeg deno                # macOS
sudo apt install ffmpeg                 # Linux (Ubuntu/Debian), then: curl -fsSL https://deno.land/install.sh | sh
```

Open a new terminal afterwards so both are on your PATH, and check with `ffmpeg -version` and `deno --version`.

Then set up Python:

```bash
git clone https://github.com/LOUYUNCHUAN/VISTA-AI.git
cd VISTA-AI
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file in the repo root with the keys you need:

```
HF_TOKEN=...              # download the dataset and trained models
ELEVENLABS_API_KEY=...    # only for generating new synthetic audio
```

Audio, features and model weights are not stored in Git. Download them from the Hugging Face dataset [`Vista-AI/CustomerServiceAudio`](https://huggingface.co/datasets/Vista-AI/CustomerServiceAudio):

```bash
python scripts/hf_dataset_sync.py download --parts metadata features models   # about 600 MB, enough to train and run the app
python scripts/hf_dataset_sync.py download                                    # everything, about 8 GB
```

## Run the app

```bash
streamlit run app.py
```

Upload an audio file, record from your microphone, or paste a YouTube URL. The app shows the V1 and V2 predictions side by side, the transcript with approximate speaker labels, and the explanation for each decision.

## Train the models

```bash
python src/train.py --stage all --rebuild_split
```

This runs stage 1 (synthetic data), stage 2 (adapter on real calls), and then scores both stages on the real-call test set. Weights are saved to `models/`.

To add your own labelled call to the stage-2 data and retrain only the adapter:

```bash
python scripts/ingest_upload.py --audio call.mp3 --label unsatisfied
python src/train.py --stage finetune --rebuild_split
```

### Generating more synthetic data

```bash
python scripts/01_generate_scripts.py --per-class 60 --long-frac 0.4   # new call scripts
python scripts/03_synthesize_audio.py --only-missing                   # voice them (ElevenLabs)
python scripts/03b_augment_audio.py --download-noise --target 2500     # noise, reverb, telephone variants
python scripts/04_extract_features.py --only syn,aug --skip-existing   # Whisper + WavLM + MPNet features
```

## Project structure

```
app.py                     Streamlit dashboard
src/
  models/architecture.py   V1 and V2 models
  models/explainer.py      Turns model attention into a readable explanation
  feature_extraction.py    Whisper -> WavLM + MPNet features
  data/dataset.py          Dataset and train/val/finetune/test split
  train.py                 Two-stage training and real-call testing
  paths.py                 All data and model paths
scripts/                   Data generation, augmentation, ingestion and Hugging Face sync
data/                      Downloaded data (not in Git)
models/                    Trained weights (not in Git)
```

More detail on the architecture, dataset and benchmark history is in [`.agents/handoff.md`](.agents/handoff.md), and the explanation layer is described in [`.agents/walkthrough.md`](.agents/walkthrough.md).
